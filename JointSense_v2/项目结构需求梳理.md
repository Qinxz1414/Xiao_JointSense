> 当前状态：已完成多模块架构、核心检测/校准/报告、品牌、本地化、交互与发布质量实施
> 状态日期：2026-08-20
> 适用分支：`codex/jointsense-v2-overhaul`
> 本文性质：项目当前实现的权威说明；历史方案、过渡架构和“待迁移”描述均不再作为实现依据。

## 1. 产品定位与使用边界

JointSense 是面向骨关节炎（OA）科研与纵向趋势观察的 Android 应用。每张测试照片固定包含横向排列的三个圆盘；用户拍摄或选择照片、对齐检测区后，应用按左 TNF-α、中 IL-6、右 IL-1β 一次得到三项浓度估算，并查看历史、趋势、OA 炎症综合指数、等级和导出报告。

应用已实现：

- 相机与 Photo Picker 选图、方向修正、采样解码、三圆盘引导裁剪、自动三因子分析、整批幂等保存和继续检测；
- TNF-α、IL-6、IL-1β 三因子浓度、范围状态和 RGB 均值/标准差记录；
- 3×3 标准梯度板校准、Blank 扣除、单调拟合、旧曲线复核和恢复出厂曲线；
- Home、Trends、Report、History、Profile、About 与检测/校准子流程；
- 结构化中英文文本/PDF 报告及系统分享；
- 跟随系统、简体中文和英文切换，并在 Activity 重建后保持导航与业务状态；
- 科研/临床专业品牌、深浅色主题、无障碍语义、非颜色图表区分和 200% 字体适配。

科学与合规边界不可弱化：

- 图像定量信号是中央椭圆 ROI 内逐像素 `B-R` 的 nearest-rank P90 手机照片色度代理；RGB 均值/总体标准差另行留作质量追溯，它们都不是酶标仪 OD；
- 标准曲线是可解释的分段线性量化，不是经临床验证的诊断模型；
- 结果仅用于科研和纵向趋势观察，不用于临床诊断、治疗决策，也不替代经验证的实验室检测；
- 固定声明仅显示在 About 页面和导出的文本/PDF 报告中；Report 与 Result 页面 UI 按产品决策不重复显示。

依赖方向：

```text
core:domain       -> Kotlin / Flow
core:analysis     -> core:domain
core:image        -> Android / ExifInterface
core:designsystem -> core:domain + Compose
```

## 4. 类型安全导航与返回行为

### 4.1 路由图

顶层路由为 `HomeRoute`、`TrendsRoute`、`ReportRoute`、`ProfileRoute`；`HistoryRoute` 和 `AboutRoute` 是从 Profile 打开的普通目的地。底栏的中央“新建检测”是动作，不是常驻 tab。

```text
MeasurementGraph(origin)
└── ImageSelectRoute -> CropRoute -> AnalysisRoute -> ResultRoute(measurementBatchId)

CalibrationGraph
└── CalibrationSelectRoute -> CalibrationCropRoute -> CalibrationAssignRoute
    -> CalibrationReviewRoute -> CalibrationDoneRoute
```

所有 graph/route 都由 Kotlin Serialization 表达；`TopLevelDestination` 带 `@Keep`，避免压缩构建破坏 enum serializer。

### 4.2 Back 与 origin

- 顶层页面保留实际访问历史；Back 返回上一个页面，最终回到 Home；只有 Home 根由 Activity/系统退出应用。
- About、History 等普通目的地 `popBackStack()` 返回来源页。
- 检测 Crop Back 返回 ImageSelect；Analysis 在尚未开始或可恢复错误时返回保留裁剪状态的 Crop。
- 分析、持久化或结果交接的关键忙碌阶段会消费 Back，避免破坏资源/提交所有权。
- Result 从活动检测图进入时，顶部 Back、系统 Back 和预测性 Back 都弹出整个 `MeasurementGraph`，回到记录的 `origin`，不会退回已完成的 Analysis。
- 从 History 打开的历史 Result 只弹出当前结果页。
- Continue measurement 先退出当前检测图，再以同一 origin 创建新 graph、新 draft。
- 校准 Back 每次退一个 typed route；Done/明确退出会弹出整个 `CalibrationGraph`。

## 5. Room 数据模型、仓库与隐私

Room 数据库 `JointSenseDatabase` 当前 schema version 为 2，导出 schema，并注册显式 `MIGRATION_1_2`。表如下：

| 表 | 主键/关系 | 主要字段 |
|---|---|---|
| `test_session` | `id` | name、createdAt、`USER/BUILT_IN` source |
| `measurement_batch` | `id`；`sessionId` 外键级联；`draftId` unique | 一张三圆盘照片的 measuredAt 与幂等草稿标识 |
| `test_result` | `id`；`sessionId` / nullable `measurementBatchId` 外键级联；batch + factor unique | 兼容旧数据的 nullable unique `draftId`、factor、concentration、rangeStatus、timestamp、`rawSignal`、`signalMethod`、6 个 RGB 特征 |
| `calibration` | factor | createdAt、version、`ACTIVE/NEEDS_REVIEW`、`signalMethod`、kit name/lot |
| `calibration_knot` | factor + position；外键级联 | concentration、raw/net/fitted signal、Blank 标记 |
| `app_metadata` | key | 迁移状态、样例初始化等稳定元数据 |

领域层定义 repository contract；`core:data` 中的 Room 实现提供 `Flow` 连续读取。生产检测使用 `commitMeasurement` 在一个 Room 事务中写入一个 batch 与三个 child result；任何 child 失败都会整体回滚。同一 `draftId` 重试返回既有 batch ID，并验证已有批次恰含三个固定因子，不重复或部分写入。旧 `commitResult` 仅保留给旧数据/兼容接口，不参与新的拍照流程。

### 5.1 内置样例与数据管理

- 首次无旧会话时初始化 12 个稳定 `BUILT_IN` 会话：9 组测试梯度和 3 组照片板数据；
- 自动初始化只发生一次，不覆盖用户数据；
- `restoreBuiltInSamples()` 显式且幂等，只恢复内置样例；
- `clearAllData()` 删除会话/结果和用户校准，并保留 `samplesInitialized=true`，重启不会自动回填；
- Profile 中恢复样例和清空全部数据都使用明确范围说明、确认对话框、加载/错误/重试状态。

### 5.2 旧数据迁移

旧 `joint_sense_data` / `joint_sense_calibration` SharedPreferences 只由 `LegacyMigrationCoordinator` 读取：

- 先严格解析全部 payload，再在一个 Room 事务中导入；任一条损坏会拒绝整批，事务回滚且不写完成标记；
- SharedPreferences 旧结果缺失的新字段映射为 `RangeStatus.UNKNOWN` 和 `draftId=null`；Room v1 结果迁移后 `measurementBatchId=null`，作为 legacy 单因子记录继续可读；旧结果的信号方法标记为 `LEGACY_MEAN_BR`，结果页明确显示“旧版 B−R 均值代理信号”，不冒充 P90；
- SharedPreferences 或 Room v1 的旧校准统一标记为 `LEGACY_MEAN_BR + NEEDS_REVIEW`。由于均值信号与新版逐像素 P90 不同域，旧曲线不得被复核提升或参与新版测量，用户必须用当前版本重新拍摄 3×3 校准板；
- `Completed` / `AlreadyCompleted` 才进入主界面；失败可 Retry；
- 用户确认“空数据库开始”时，清理可能的部分 Room 数据并写 `SKIPPED_BY_USER`，但不删除旧文件；
- 跳过、失败和取消都不会偷偷把损坏数据当空数据成功。

生产代码中允许的 SharedPreferences 仅有两处：上述只读旧数据迁移来源，以及相机权限是否曾请求的历史。Room 是活动业务存储。

### 5.3 敏感数据备份策略

研究/健康测量只保存在应用本地。manifest 设置 `android:allowBackup="false"`；Android 12+ 的 data-extraction rules 同时排除 cloud backup 与 device transfer 的 root/file/database/sharedpref/external 及 device-protected 域。仓库中不保留默认备份 TODO 模板。

## 6. 图片与检测流水线

`core:image` 的 `SampledBitmapDecoder` 在 IO dispatcher 执行 bounds pass、2 的幂采样解码和 EXIF pass：最长边目标 2048，处理 4097 等向上边界，支持 90/180/270 度旋转。错误区分 Unsupported、Unreadable、OutOfMemory；成功才转移 bitmap 所有权，替换、失败和取消会释放本地资源。

检测流程：

```text
AwaitingImage -> Decoding -> ReadyToCrop -> ReadyToAnalyze
              -> Analyzing -> Persisting -> Success
              -> RecoverableError -> Retry(resumeStage)
```

- Photo Picker 使用 `PickVisualMedia(ImageOnly)`；尽量保留 provider 读权限，不支持时复制到 app-owned cache；
- 相机临时文件位于 `<cacheDir>/measurement` 的直接子项，URI/规范路径/token 一致时才允许删除；
- 裁剪框必须覆盖一条横向三圆盘区域：宽至少 144 px、高至少 48 px、宽高比 2.4–4.2；默认框按图像宽度 80%、约 3:1 居中生成；
- 裁剪区按像素边界等分为三列，固定物理映射为左 TNF-α、中 IL-6、右 IL-1β；每列只采样中央椭圆 ROI（横纵半径均为对应单元尺寸的 30%），引导圈与实际算法区域一致，盘外背景不进入统计；
- 每个圆盘独立使用 Welford 算法计算 RGB 均值与总体标准差；用于曲线反算的 `rawSignal` 则统一为 ROI 内逐像素 `B-R` 的 nearest-rank P90，并持久化方法版本 `PIXEL_BR_P90_V1`，与 `Rule/_pgmL_estimate.md` 的出厂曲线来源一致；不透明覆盖不足、区域过小或方向/比例错误会进入可恢复错误，不产生部分结果；
- 一次分析只读取一份校准快照，对三个因子分别使用活动用户校准，否则使用对应 `FactoryCurves`；不经过占位回归模型；
- operation generation、draft identity 和 immutable snapshot 保证重复点击/晚到协程不会污染新流程；
- 裁剪确认后自动进入 Analysis 并开始三因子处理；repository 返回完整 batch ID 后才进入 Success；持久化 Retry 复用同一 draft ID；
- 读取、解码、裁剪、分析、持久化、权限和文件清理错误均有可见状态和 Retry。

`SavedStateHandle` 保存 Bundle-safe 的 origin、draft、session、URI、crop 四边/确认态、权限/相机请求 token、清理警告和待确认 batch ID。Activity/进程内重建时 URI、crop、draft、session、origin 和当前 route 均可恢复；不再保存可选 factor，因为三因子和物理顺序属于固定检测协议。bitmap 本身重新解码且 crop 重新校验实际尺寸。

相机权限采用 durable intent + request claim/ack/rollback 协议。首次点击不会在权限历史 IO 期间丢失；重复点击合并；同步 launcher 失败可恢复；过期 draft/token 的 Activity Result 被忽略；普通拒绝可重试，永久拒绝提供系统设置入口。

## 7. 校准与科学量化

### 7.1 校准验证

校准严格要求：

1. 恰好 9 条有限 raw signal；
2. 浓度文本按精确十进制语义解析，拒绝空白、非法、负数、NaN、Infinity、溢出和非零下溢；
3. 恰好一个 `concentration == 0` 的 Blank，非 Blank 浓度唯一；
4. `netSignal = rawSignal - blankRawSignal`，结果必须可表达为有限 Float；
5. net dynamic range 至少 8.0；
6. 按浓度排序后用 adjacent-block PAVA 得到非递减 fitted signal；
7. 单点允许修正为 `max(3.0, rawDynamicRange × 0.15)`，超过则 `NonMonotonicBeyondTolerance`；
8. 只有 `CalibrationValidation.Valid` 可保存为 `ACTIVE`。

校准的 3×3 每孔也使用中央 60% 椭圆与同一个 nearest-rank P90 工具提取 `B-R`，新曲线写入方法版本 `PIXEL_BR_P90_V1`，避免用户曲线、出厂曲线和实际测量处于不同信号域。旧版 `LEGACY_MEAN_BR` 曲线只保留审计记录，不能提升或量化。校准保留 raw/net/fitted、孔位置、浓度、Blank、试剂盒名称/批号。Select → Crop → Assign → Review → Done 共用 graph-scoped `CalibrationViewModel`；factor、浓度原文、9 个 readings、URI、crop 和完成标记可重建。detect/save/restore 为 single-flight，busy 时锁定冲突输入。用户保存、当前域曲线复核和 factory clear 共用进程 Mutex，避免互相覆盖。

### 7.2 StandardCurve

- 节点要求浓度有限非负且严格递增，信号有限且非递减；测量输入必须有限；
- 节点间分段线性插值；低于首信号返回 0/`BELOW_RANGE`；高于末信号返回末浓度/`ABOVE_RANGE`，不外推；
- 精确平台采用右连续逆，返回整个平台最高浓度；
- 中间和最终浓度必须保持有限、非负且能以 Float 表达。

### 7.3 OA 炎症综合指数与等级

因子 caps：TNF-α 500、IL-6 1000、IL-1β 500 pg/mL；权重分别为 0.40、0.35、0.25。每项先按 cap 归一化到 0–1，再加权。Result 只在当前照片三项均完整有效时生成 OA 指数/等级，绝不从同一会话的其他照片补齐缺项；趋势等兼容旧数据的聚合逻辑仍可对既有单因子历史按现有权重归一化。空输入返回无指数；非有限输入被拒绝。

| 等级 | AI 区间 | 当前显示语义 |
|---|---|---|
| 0 | `[0, 0.25)` | 无风险 / No risk |
| 1 | `[0.25, 0.50)` | 轻度 / Mild |
| 2 | `[0.50, 0.75)` | 中度 / Moderate |
| 3 | `[0.75, 0.90)` | 重度 / Severe |
| 4 | `[0.90, 1.00]` | 极重度 / Very severe |

## 8. 洞察、报告与术语

Home 显示当前 OA 炎症综合指数、等级、三因子最新值/小趋势和最近 AI 序列；Trends 支持 7/30/90 天及全部范围，显示三因子、AI 和关键事件；History/Settings/Insights 的检测次数统一按照片批次计数，一张照片的三个 result 只算一次。History 显示完整会话摘要并将“打开”和“删除”分成独立动作。

Report 页面 UI 由 `ReportPresentation` 驱动，展示当前 AI/等级、三因子最新值及周比较、OA 周变化与趋势解释、科研趋势建议和导出动作。导出文本/PDF 则由 `ReportModel`、`LocalizedReportFormatter` 和 PDF exporter 驱动，除 AI/等级、最新因子值、周变化和建议外，还加入生成时间与固定免责声明；两种表面不是同一字段集合。逐条检测的定量范围状态在 Result 页面展示，分析方法说明在 About 页面展示，当前导出 formatter 不重复这两类内容。PDF 支持多页、重复页眉、安全换行、同名冲突避免、完整写入后成功、分享失败反馈和 exactly-once 资源清理。

About 的中英文方法说明与实现保持同一语义：左/中/右三个固定圆盘 ROI 分别提取 RGB 质量追溯统计量，标准曲线输入为中央椭圆内逐像素 `B−R` nearest-rank P90；仅同属 `PIXEL_BR_P90_V1` 的用户校准可参与量化。当前照片 Result 必须具备完整三因子，缺项权重重归一化只用于兼容旧历史/趋势聚合。

术语统一：

- `OA inflammation index (AI)` / `OA 炎症综合指数（AI）`；
- TNF-α、IL-6、IL-1β，浓度单位统一 `pg/mL`；
- “grade/等级”表示科研趋势分层，不称临床诊断分级；
- “B−R P90 色度代理信号”与 OD 明确区分；RGB 均值差不冒充实际曲线输入。

## 9. 多语言与重建

语言选项为 `SYSTEM("")`、`SIMPLIFIED_CHINESE("zh-CN")`、`ENGLISH("en-US")`。`AppCompatLanguageController` 是唯一 application locale 写入口，Profile 的语言选择先关闭对话框再应用，避免窗口生命周期冲突。

- base `values` 为英文，`values-zh-rCN` 为简体中文；资源 key parity 和术语测试保护同步；
- Home、Trends、Report、检测、历史、校准、Profile、About、错误/权限/无障碍文本均已资源化；
- 新会话名称在用户操作发生时使用当前语言前缀（`Test #n` / `检测 #n`），而不是在 ViewModel 构造时冻结；
- Profile 和 About 在 `en -> zh-CN -> en` Activity 重建中保留 route；

## 10. 品牌、UI、交互与无障碍
