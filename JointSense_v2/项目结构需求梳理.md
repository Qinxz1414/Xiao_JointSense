# JointSense v2 — 项目结构需求梳理（复盘文档）

> 生成日期：2026-08-07
> 用途：沉淀 JointSense 安卓端（ELISA 炎症因子检测 + OA 炎症指数）的整体结构、需求与关键设计决策，便于后续复盘与接手。

---

## 1. 项目定位与目标

**JointSense** 是一款面向骨关节炎（OA）患者的安卓应用：用户拍摄 ELISA 检测板照片，App 自动识别三个炎症因子的孔内色度信号，反算 `pg/mL` 浓度，并合成一个 **OA 炎症指数（AI，0~4 级）** 用于病情活动度评估与趋势追踪。

核心目标（需求来源）：
- 三个炎症因子定量：**TNF-α、IL-6、IL-1β**，单位统一 `pg/mL`。
- 从 ELISA 板照片（非酶标仪 OD）估算浓度 → 这是本项目的核心约束，决定了"色度代理"而非"OD 4PL"的技术路线。
- 内置一批已量化的检测数据，首次启动即有内容（不空屏）。
- 提供**引导式校准**：用户可用试剂盒标准梯度假板重新拟合曲线。
- 提供历史、趋势、报告、个人中心等完整工作台。

## 4. 核心数据流（实时拍摄路径）

```
拍照/选图 (IMAGE_SELECT)
   → 裁剪板区 (IMAGE_CROP, ImageCropView)
   → 选因子 (FACTOR_SELECT)
   → analyze()：
        1. FeatureExtractor.extract(crop) → 6 特征 [rMean,gMean,bMean,rStd,gStd,bStd]
        2. tealness = bMean − rMean
        3. StandardCurve.concentrationFor(tealness, factor) → pg/mL   ← 插补
        4. 生成 TestResult，塞入 currentSession（≤5 条/会话）
        5. TestRepository 落盘
   → RESULT 展示 + 可继续测试
```

落盘后，Home/Trends/Report 通过 ViewModel 派生统计实时刷新。

## 5. ELISA 量化模型（关键算法）

### 5.1 信号度量
- **孔内色度信号 = `tealness = B − R`**（蓝绿染色越正，浓度越高）。
- 依据 `Rule/SKILL.md`：ELISA 孔内色板从透明灰 `#9B9790` 到深青 `#6F8685`，即 B 通道相对 R 通道偏高。
- `FeatureExtractor` 用矩形区（而非圆/峰值）取均值+标准差，规避脆弱的圆心检测。

### 5.2 标准曲线插补 `StandardCurve`
- 输入信号 `tealness`，输出浓度 `pg/mL`，**分段线性插值**（"插补"）于 `(concentration, signal)` 节点之间。
- **出厂节点（FACTORY_KNOTS）** 由 `Rule/` 资产（测试用例 + 样本 + 3 张剪贴板板）用 90 分位液体像素 tealness 拟合得出，仅为"照片色度序数估计"。
- 低于首节点信号 → 0；高于末节点 → 封顶（不外推）。
- **曲线可覆盖**：`setKnots(Calibration)` 由校准流程写入；`resetKnots()` 还原出厂。
- 上限 `maxConcentration`：TNF-α/IL-1β = 500，IL-6 = 1000（取自样本梯级顶点）。

### 5.3 OA 炎症指数 `OaIndex`
- 对各因子浓度按 `caps` 归一化到 0~1，按权重合成 AI（0~1）：
  - 权重：`TNF_ALPHA 0.40 / IL6 0.35 / IL1_BETA 0.25`（TNF 优先）。
- 分级（设计规格，见 `Rule/界面.png`）：

  | 等级 | 区间 | 含义 |
  |---|---|---|
  | 0 | [0.00,0.25) | No risk / 极低活动 |
  | 1 | [0.25,0.50) | Mild |
  | 2 | [0.50,0.75) | Moderate |
  | 3 | [0.75,0.90) | Severe |
  | 4 | [0.90,1.00] | Very severe |

- 附带 `wellColor(intensity)`（色板映射）、`aiSeries`（时序）、`suggestions(grade, 周环比)`（报告建议）。
- **`caps` 已从占位值 6/8/4 修正为 500/1000/500**，避免真实数据在 grade 4 饱和。

### 5.4 已旁路的占位模型 `PredictionModel`
- Lasso 选出的 6 特征线性模型，**系数是占位值**。当前 `analyze()` 实际走 `StandardCurve`，未调用它；保留作说明/未来 `.tflite` 替换入口。

## 6. 校准体系（引导式）

- 入口：Profile → **Calibrate Standard Curve**。
- 5 步流程 `CalibrationFlowScreen`：SELECT → CROP → ASSIGN（选因子、预填出厂梯级浓度）→ REVIEW（自动空白扣除：减去 conc=0 的 Blank 孔信号）→ DONE（保存）。
- `CalibrationDetector.detectGridSignals()`：把裁剪板按 3×3 网格切分，测每孔中心液体区 tealness。
- `CalibrationManager`：
  - 持久化到新 SP `joint_sense_calibration`，按因子合并；
  - `init(application)` 在 ViewModel `init` 时加载并 `StandardCurve.setKnots()`；
  - `clear()` 还原出厂曲线。
- ViewModel 暴露 `hasUserCalibration` / `calibrationFactorCount` 供 Profile 显示状态。

## 7. 内置数据 `BuiltInData`

- 首次启动（`loadSessions()` 为空）时填充 **12 个 TestSession**：
  - 9 张 `测试用例.pptx` 实测板（真实浓度，时间 2026-07-28 ~ 08-05）；
  - 3 张剪贴板照片板（浓度经 `StandardCurve` 由实测信号插补）。
- 用户数据永远优先（只在空库时写入）。`clearAllData()` 后下次启动会重新填充。

- `hasUserCalibration` 属性访问错误已修正。

### ⚠️ 已知约束 / 风险
1. **当前命令行尚未完成 Gradle 构建**：2026-08-07 检查时 shell 未配置 `JAVA_HOME`，现有 Kotlin 不能视为已编译验证；后续必须定位兼容 JDK 并运行完整测试、Lint 与 Debug 构建。
2. **"照片色度代理"非 OD 4PL**：浓度是序数估计，非临床级。真正精度需酶标仪 OD450 + 四参数 logistic 拟合——届时仅替换 `StandardCurve` 节点即可，UI/Manager 不动。
3. **样本.pptx 标准板为整板照片、无孔位-浓度布局说明**，照片→浓度校准仅靠 `测试用例.pptx` 已知浓度作为地面真值。
4. **`PredictionModel` 系数占位**：若启用需替换真实训练参数或 `.tflite`。
5. **持久化无迁移**：未来改 `TestResult` 字段要小心旧数据。
6. **临时文件**：`Rule/_std/`、`~$测试用例_炎症因子标注.pptx` 无害，可手动删除。
7. **导航编译缺陷**：`MainActivity.kt` 当前存在重复 `FlowScreen.CALIBRATION` when 分支。
8. **标准曲线插值缺陷**：`StandardCurve.concentrationFor()` 当前把浓度和信号变量反向解构，必须以回归测试锁定后修复。
9. **校准输入缺陷**：缺少 Blank 时会把第 1 孔当 Blank，非数字输入会静默变为 0；保存前缺少完整科学有效性验证。
10. **图片与错误处理风险**：图片全尺寸解码和分析在主线程执行，权限、损坏图片与解码失败缺少用户可见反馈。
11. **持久化风险**：旧 JSON 任一解析异常即返回空列表，可能被误判为首次启动；清空后重启又自动恢复样例。
12. **报告风险**：PDF 单行绘制不自动换行，长英文和中文报告可能被裁切。

### 🔁 复盘建议 / 下一步
- 在 Android Studio 验证构建，跑一次真机校准流程。
- 定义"标准梯度假板"的**明确孔位-浓度版式**（如固定 3×3 第1列 Blank），让 `CalibrationDetector` 更稳。
- 评估引入 Room + 协程、数据版本迁移。
- 评估把 `PredictionModel` 替换为真实模型（若团队有训练产物）。
- 把"OD450 + 4PL"作为精度升级路线图，标注在 `StandardCurve` 注释中已留好入口。

## 12. 已确认的全面升级设计（目标状态，尚待实施）

> 设计确认日期：2026-08-07
> 正式规格：`docs/superpowers/specs/2026-08-07-jointsense-v2-overhaul-design.md`

用户选择全面升级路线，不采用仅修补现有单模块代码的方案。升级分为三个连续阶段，但全部属于本次任务范围：

1. **架构底座**：多模块、类型安全 Navigation Compose、Room、协程/Flow、旧 SharedPreferences 无损迁移和中英文切换。
2. **检测体验与缺陷修复**：图片管线、检测/校准状态机、错误恢复、幂等写入、算法和交互回归修复。
3. **品牌与发布质量**：A「关节信号」矢量 Logo、临床工作台视觉、双语报告、无障碍和完整验证。

### 12.1 目标模块

```text
:app
├── :feature:insights       # Home / Trends / Report
├── :feature:measurement    # 拍摄 / 裁剪 / 检测 / 结果 / 历史
├── :feature:calibration    # 标准曲线校准
├── :feature:settings       # Profile / 语言 / 关于 / 数据管理
├── :core:domain            # 领域模型、仓库接口、用例
├── :core:analysis          # RGB、标准曲线、校准验证、OA 指数
├── :core:designsystem      # 主题、组件、Logo、公共资源
├── :core:data              # 仓库实现、样例、旧数据协调迁移
└── :core:database          # Room entities、DAO、schema

build-logic                 # Gradle 约定插件
```

`:app` 只负责装配、NavHost、底栏和显式 `AppContainer`。功能模块不直接访问 DAO，也不相互引用内部实现。算法层保持纯 Kotlin，不再引用 Compose `Color`。

### 12.2 导航与返回

- 顶部返回、系统返回和预测性返回使用同一 NavController 返回栈。
- 检测前三步与校准各步骤逐级返回。
- 检测 Result 是已提交终点，返回发起检测前的页面，避免重复写入。
- 顶层页面按访问历史返回，最后回到 Home；只有 Home 根页面再次返回才退出。
- 图片使用 URI，草稿用 `SavedStateHandle` 保存，支持旋转和语言切换恢复。

### 12.3 Room 与数据策略

- Room v1 表结构：

  | 表 | 主键/关系 | 核心字段 |
  |---|---|---|
  | `test_session` | `id` | `name`, `createdAt`, `source: USER/BUILT_IN` |
  | `test_result` | `id`; `sessionId` 外键级联 | `factor`, `concentration`, timestamp, 6 个 RGB 特征, `rangeStatus`, nullable unique `draftId` |
  | `calibration` | `factor` | `createdAt`, `version`, `status: ACTIVE/NEEDS_REVIEW` |
  | `calibration_knot` | `factor + position`; 外键级联 | concentration, raw/fitted signal, `isBlank` |
  | `app_metadata` | key | legacy migration、样例初始化和审计标记 |

- 旧检测与校准 JSON 在单一事务中完整验证和导入，成功前不写迁移标记；旧 SP 暂留为只读回退。
- 旧结果缺少范围信息时迁移为 `UNKNOWN`；旧校准不符合新规则时保留为 `NEEDS_REVIEW`，但不应用到新检测。
- 迁移失败显示恢复界面，不写样例；用户二次确认放弃迁移时记录 `SKIPPED_BY_USER` 和 `samplesInitialized=true`，旧 JSON 仍不删除。
- 内置 12 板标记为 `BUILT_IN`，只首次安装初始化。
- “清空全部数据”统一删除用户检测、样例和用户校准，但保留已初始化标记，重启不回填。
- 个人中心提供显式“恢复样例数据”，只恢复样例，不恢复校准。

### 12.4 多语言与专业文案

- 支持简体中文和英语，默认跟随系统。
- 个人中心提供“跟随系统 / 简体中文 / English”。
- 中文采用科研/临床专业表达；数据库不保存本地化名称。
- Android 7–12 通过 AppCompat locales 兼容，Android 13+ 与系统应用语言设置同步。
- “关于”和导出报告标注：照片色度结果仅供科研与趋势观察，不作为临床诊断依据；结果页不重复显示。

### 12.5 交互与错误处理

- 检测状态：等待图片 → 解码 → 裁剪 → 待分析 → 分析 → 写入 → 完成/可恢复错误。
- 相册改用系统 Photo Picker；图片按目标尺寸采样解码。
- IO、算法和数据库任务通过协程分派，Compose 用生命周期感知方式订阅 StateFlow。
- 权限、图片、分析和写入错误均显示原因与可执行恢复操作，不再静默吞掉。
- `draftId` 唯一索引确保重复点击和重试不会重复落库。
- 定量曲线低于最低信号返回 `0 + BELOW_RANGE`，范围内插值，高于最高信号返回最高节点浓度并标记 `ABOVE_RANGE`；OA `caps` 不作为曲线端点。
- 校准要求 9 个有效读数、恰好一个 Blank、非负且非 Blank 唯一浓度、净信号动态范围至少 `8.0`，并采用单调拟合。
- 单调拟合最大单点调整为 `max(3.0, 原始动态范围 × 15%)`；超过即阻止保存并要求重拍、重裁或修正孔位。

### 12.8 已纳入回归的缺陷

1. 重复 `FlowScreen.CALIBRATION` when 分支。
2. `StandardCurve.concentrationFor()` 浓度/信号变量反向解构。
3. 曲线末节点与 OA 最大浓度映射含义混用。
4. 缺失 Blank 时错误使用第 1 孔，非法输入静默变为 0。
5. 图片主线程全尺寸解码、同步分析和不可见进度。
6. 相机权限、损坏图片和解码失败无可见错误。
7. 相机返回和语言切换可能丢失 `photoUri`/校准草稿。
8. 手写 JSON 任一异常返回空列表，并可能触发错误样例回填。
9. 清空后重启自动恢复样例。
10. 删除会话后 `sessions.size + 1` 可能生成重复名称。
11. PDF 单行绘制导致长文本和中文裁切。
12. 算法层引用 Compose `Color`，阻碍纯 Kotlin 模块隔离。
13. UI 文案与无障碍描述几乎全部英语硬编码。
