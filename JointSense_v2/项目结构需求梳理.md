## 1. 产品定位、用户价值与合规边界

JointSense 面向骨关节炎（OA）科研与纵向趋势观察场景。用户通过安卓手机拍摄 ELISA 检测板，应用提取孔内照片色度代理信号，估算 TNF-α、IL-6、IL-1β 浓度（统一单位 `pg/mL`），并合成 0–1 的 OA 炎症指数及 0–4 级分层，用于历史、趋势和报告展示。

核心产品目标：

- 支持拍照和相册选图、裁剪、因子选择、分析、结果保存与继续检测。
- 支持 TNF-α、IL-6、IL-1β 三因子量化，保存原始 RGB 均值/标准差、浓度和范围状态。
- 支持标准梯度板引导式校准、旧校准复核、恢复出厂曲线。
- 支持历史、趋势、结构化文本报告和 PDF 导出/分享。
- 首次安装在无旧数据时提供 12 条稳定内置样例，避免空白首页。
- 支持跟随系统、简体中文 `zh-CN` 和英语 `en-US`。
- 返回键回到上一个页面；只有 Home 根页面再次返回才交由 Activity/系统退出应用。

科学与合规边界：照片 `tealness = B - R` 是色度代理，不是酶标仪 OD，也不是经临床验证的 4PL 定量。不得把本应用结果用于临床诊断、治疗决策或替代经验证的实验室检测。导出报告已使用以下固定声明；关于页仍须在 Phase 3 接入同一声明，检测 Result 页面不显示声明。

- 中文：本报告结果基于手机照片色度代理估算，仅供科研与纵向趋势观察，不作为临床诊断、治疗决策或替代经验证实验室检测的依据。
- English: Results in this report are estimates derived from smartphone-photo colorimetry for research and longitudinal trend observation only. They are not intended for clinical diagnosis, treatment decisions, or as a substitute for validated laboratory testing.

## 5. Room、仓库、内置数据与旧数据迁移

### 5.1 Room v1

| 表 | 主键/关系 | 核心字段与约束 |
|---|---|---|
| `test_session` | `id` | `name`、`createdAt`、`source: USER/BUILT_IN` |
| `test_result` | `id`；`sessionId` 外键级联 | factor、concentration、timestamp、6 个 RGB 特征、`rangeStatus`；nullable `draftId` 唯一索引 |
| `calibration` | `factor` | `createdAt`、version、`status: ACTIVE/NEEDS_REVIEW`、kit name/lot |
| `calibration_knot` | `factor + position`；外键级联 | concentration、raw/net/fitted signal、`isBlank` |
| `app_metadata` | key | 旧迁移状态、样例初始化和审计标记 |

Repository 连续读取返回 `Flow`；跨表写入和清空使用 Room transaction。`commitResult(sessionId, draftId, result)` 以唯一 `draftId` 实现幂等：重试返回现有结果 ID，不创建第二条结果。

### 5.2 旧 SharedPreferences 迁移

- 只读来源为 `joint_sense_data` 与 `joint_sense_calibration`。
- `LegacyJsonParser` 严格要求 ID、enum 和数值字段；第二条数据损坏也会拒绝整份 payload，不以空列表掩盖错误。
- 协调器先完整解析，再在一个 Room 事务导入；失败时导入 0 行且不写完成标记。
- 旧结果缺少新字段时使用 `RangeStatus.UNKNOWN`、`draftId=null`。
- 结构可读的旧校准先保存为 `NEEDS_REVIEW`，不会直接激活。
- `MigrationGate` 只有在 `Completed`、`AlreadyCompleted` 或用户确认的 `SkippedByUser` 后才组合 NavHost。失败页提供 Retry 和二次确认的空库起步。
- `skipLegacyAndStartFresh()` 清理部分 Room 数据并写 `SKIPPED_BY_USER`、`samplesInitialized=true`，但不删除旧 SharedPreferences。

### 5.3 内置数据与清空语义

- 无旧会话且首次初始化时写入 12 条稳定 ID 的 `BUILT_IN` 会话：9 张测试板实测数据 + 3 张照片板插补数据。
- 自动初始化只执行一次，不覆盖用户数据。
- `clearAllData()` 删除测试会话/结果和用户校准，但保留 `samplesInitialized=true`，重启不会偷偷回填样例。
- `restoreBuiltInSamples()` 是显式、幂等的恢复动作，只恢复样例，不恢复用户校准。完整 Profile 操作入口仍属 Phase 3。

## 6. 科学分析与精确边界

### 6.1 图像信号与特征

- 孔内照片色度信号固定为 `tealness = bMean - rMean`；蓝绿染色越强，信号越高。
- 结果保存 RGB 三通道均值与标准差；科学单位始终为 `pg/mL`。
- 不启用历史 `PredictionModel` 的占位 LASSO 系数；production 量化使用经验证的 `StandardCurve` 路径。

### 6.2 出厂标准曲线常量

以下 `(concentration pg/mL, signal)` 节点从旧实现原样迁入 `FactoryCurves`：

- `TNF_ALPHA`：`(0,-8)`、`(20,-4)`、`(50,0)`、`(100,20)`、`(200,26)`。
- `IL6`：`(0,-7)`、`(50,-4)`、`(100,0)`、`(200,0)`、`(500,11)`。
- `IL1_BETA`：`(0,-11)`、`(20,17)`、`(50,17)`、`(100,20)`、`(200,33)`。

`StandardCurve` 的 production 行为：

- 输入是信号，输出是浓度；节点之间分段线性插值。
- 测量信号必须有限；曲线至少两个有效节点，浓度严格递增，信号非递减。
- 低于首信号：`concentration=0`、`BELOW_RANGE`。
- 精确命中首节点：返回首节点浓度、`IN_RANGE`。
- 高于末信号：返回末节点浓度、`ABOVE_RANGE`；不外推，也不跳到 OA cap。
- 精确命中等信号平台时使用右连续逆：返回完整平台中最高浓度。因此 IL-6 `signal=0` 返回 `200`，IL-1β `signal=17` 返回 `50`。

### 6.3 OA 炎症指数

- caps：TNF-α `500`、IL-6 `1000`、IL-1β `500`。
- weights：TNF-α `0.40`、IL-6 `0.35`、IL-1β `0.25`。
- 缺少某因子时只在现有因子权重内重新归一化；空输入返回无指数。
- 非有限浓度或非有限 AI 被拒绝，不会被 clamp 成看似合理的值。

| 等级 | AI 区间 | 语义 |
|---|---|---|
| 0 | `[0.00, 0.25)` | No risk / 极低活动 |
| 1 | `[0.25, 0.50)` | Mild |
| 2 | `[0.50, 0.75)` | Moderate |
| 3 | `[0.75, 0.90)` | Severe |
| 4 | `[0.90, 1.00]` | Very severe |

### 6.4 校准输入、PAVA 与激活规则

校准验证必须同时满足：

1. 恰好 9 条读数，且所有 raw signal 有限。
2. 浓度文本经精确十进制语义解析；空白、非法、负数、NaN、Infinity、溢出或非零数下溢为 Float 零均为 Invalid，绝不使用 `toFloatOrNull() ?: 0`。
3. 浓度非负；恰好一个 `concentration == 0` 的 Blank；所有非 Blank 浓度唯一。
4. 每孔 `netSignal = rawSignal - blankRawSignal`。
5. `rawDynamicRange = max(netSignal) - min(netSignal)` 必须至少 `8.0`；`7.999` 拒绝，`8.0` 接受。
6. 按浓度排序后运行 adjacent-block PAVA，得到单调非递减 `fittedSignal`。
7. 最大允许单点修正为 `max(3.0, rawDynamicRange * 0.15)` tealness；等于阈值接受，超过阈值返回 `NonMonotonicBeyondTolerance`。
8. raw/net/fitted 在进入公开 Float knot 前必须仍有限且可表达。

只有 `CalibrationValidation.Valid` 能保存为 `CalibrationStatus.ACTIVE`。持久化保留每个 knot 的 well index/position、concentration、raw、net、fitted 和 Blank 标记。

## 7. 图片解码、相机与文件所有权

共享 Android 图片处理位于 `:core:image`，检测和校准都依赖它而不互相依赖。

- `SampledBitmapDecoder.decode(uri, maxEdge=2048)` 在 IO dispatcher 上执行 bounds pass、sampled decode 和独立 EXIF pass。
- `calculateInSampleSize` 返回满足最长边严格不超过上限所需的最小 2 的幂；使用向上取整语义处理 `4097/2048` 边界，并拒绝不可表示的 2 的幂。
- EXIF 90/180/270 度会旋转输出；返回原始尺寸、sample size 和 rotation degrees。
- 错误是 typed `Unsupported`、`Unreadable`、`OutOfMemory`，不返回 null，也不静默吞掉异常。
- 解码、旋转、dispatcher prompt-cancellation 和后续失败都遵守统一 bitmap ownership；替换/失败/取消释放本地资源，成功才转移所有权。
- 测量相机临时文件只能位于 `<cacheDir>/measurement` 的直接子项；`SavedStateHandle` 保存 URI、规范路径和 token。重试/重建保留文件，成功持久化或明确取消只删除自己拥有且匹配 token 的文件。
- Photo Picker 使用 `PickVisualMedia(ImageOnly)`。优先获取持久读取权限；不支持时复制到 app-owned cache。provider URI 从不交给删除逻辑。

设备侧真实 BitmapFactory/EXIF、Activity Result 时序与强制 OOM 仍缺少通过的 connected-device 证据，详见第 14.3 节。

## 8. 检测状态机、交互与返回逻辑

### 8.1 状态与持久化

`MeasurementViewModel` 的单一 `StateFlow<MeasurementUiState>` 是业务事实来源，核心阶段为：

```text
AwaitingImage -> Decoding -> ReadyToCrop -> ReadyToAnalyze
             -> Analyzing -> Persisting -> Success
             -> RecoverableError -> Retry(resumeStage)
```

`SavedStateHandle` 只保存 Bundle-safe primitives：origin、draft UUID、session、URI、crop 四边、crop-confirmed、factor、权限/启动协议 token 等。URI、crop、factor、origin 和 draft 可跨重建恢复；恢复的 crop 必须重新校验实际解码尺寸。

### 8.2 单飞、幂等与错误恢复

- Analyze/Save 使用 operation identity、generation 和 immutable snapshot；重复点击不会重复分析/提交。
- IO 用于解码/文件/repository；Default 用于特征提取与插值；Success 只能在 repository 返回后发布。
- persistence retry 使用相同 draft ID；Room 唯一索引保证重复提交仍只产生一个结果。
- 不合作的旧 operation 完成后必须验证 token/draft/stage，不能污染新流程、释放新图片或发送旧导航 effect。
- `RecoverableError` 保留 URI/crop/factor/draft/origin 和 `resumeStage`。所有权限、读取、解码、裁剪、分析、持久化与临时文件清理问题都有可见错误/Retry；不存在仅 `printStackTrace()` 或 silent return。
- session 名称算法使用注入前缀下的最大数字后缀 + 1，例如 `Test #1, Test #3 -> Test #4`，避免删除中间会话后重名。当前生产 composition root 尚未注入本地化前缀，因此仍使用 factory 默认值 `Test`；语言相关前缀属于 Phase 3。

### 8.3 相机权限与 Activity Result 协议

- 首次点击 Take Photo 在权限历史读取期间会保留一个 durable queued intent；重复点击合并为一个。
- 权限请求只有“持久写入已请求历史 → effect → claim → launcher 返回后 acknowledge”一条路径。
- 同步 launcher 失败会 rollback 为可见 `PermissionLaunchFailed`；Retry 重发同一 pending 请求，不重复写权限历史。
- 未 acknowledge 的请求重建后可重新发出；已 acknowledge 的请求不会重复启动系统对话框。
- 权限结果携带 request/draft claim；旧草稿、已离开 `AwaitingImage` 或无 active request 的 callback 被忽略。
- Gallery、直接选图、新 draft、Back/cancel 和流程清理都会取消并失效旧权限/相机所有权。
- 永久拒绝显示 Open settings；普通拒绝保留可重试状态。

### 8.4 页面栈与 Back

```text
MeasurementGraph(origin)
└── ImageSelect -> Crop -> FactorSelect -> Result(resultId)
```

- Crop Back：先把状态退回 ImageSelect，再 pop 一个 route。
- Factor Back：状态回到已保留 crop，再 pop 到 Crop。
- 分析、持久化和结果 handoff 忙时会消费 Back，避免中途退出破坏所有权。
- Result Back/顶部 Back/系统或预测性 Back：移除整个 MeasurementGraph，回到发起检测的顶层目的地；绝不回到 FactorSelect。
- Continue measurement：先返回 origin，再打开新的 MeasurementGraph；新 graph 的 ViewModel 创建新 draft ID，不在旧 graph 内堆叠。
- 顶层 Home/Trends/Report/Profile 遵循访问历史返回，最终回到 Home；只有 Home 根页面的返回才退出应用。

## 9. 校准状态机、旧曲线复核与并发一致性

### 9.1 五个真实 typed routes

```text
CalibrationGraph
└── Select -> Crop -> Assign -> Review -> Done
```

App 拥有 routes/NavHost 注册；feature 暴露五个真实 route screen entry。一个以 `CalibrationGraph` back-stack entry 为 owner 的 `CalibrationViewModel` 跨五步存活。顶部、系统和预测性 Back 每次只 pop 一个 route；Done 明确退出整张 graph。

### 9.2 状态与操作

- `SavedStateHandle` 保存 factor、浓度原文、9 个 readings、URI、crop、review/save 完成标记；scientific validation 从输入重算，不序列化陈旧结论。
- factor 改变会加载对应 factory ladder；非法文本保留字段错误。
- 3×3 `GridSignalDetector` 使用采样且方向正确的图片，按行优先读取每孔中心区域；空、反向、负数、越界、溢出 crop 均在像素访问前拒绝，合法 1×1 边界安全。
- Save 只接受 Valid，写入一个 factor，不能删除其他 factor 的有效曲线；完成状态 durable，导航 claim 一次性，重建或从 Done 返回不会重复写。
- Save、restore、detect 都 single-flight；busy 时拒绝互斥的 factor/text/signal/image/crop/reset/Back 操作。
- “Restore factory curves” 必须二次确认，通过统一协调器执行 `clearAll()`，删除所有用户校准。成功后仍停留 Done 显示结果，等待用户 Done/Another/Back。

### 9.3 旧 `NEEDS_REVIEW` 曲线

- `LegacyCalibrationRevalidator` 由 `AppContainer` 进程级持有，对 snapshot 做有限一次扫描。
- 同一科学 validator 通过才从 `NEEDS_REVIEW` 提升为 `ACTIVE`；确定性 Invalid 保留 review 状态；验证/保存异常和 cancellation 保持可 Retry。
- Settings 独立显示 active count 与 review count；review-required 优先于“没有用户曲线”。Select 页提供独立 legacy warning/Retry，不覆盖一般 decode/detect/save 错误。
- 普通用户 Save、旧曲线 promotion 与 factory `clearAll()` 共用同一个 process Mutex：旧保存先开始时用户保存最后获胜；用户先完成时旧扫描看到 ACTIVE 不覆盖；任一方向取消都会释放锁。

## 10. 报告、本地化格式与 PDF

### 10.1 已提交的 Task 7 报告实现（`8f34c28`、`3c8445c`）

### 10.2 已验证并提交的 Task 7 修复（`3c8445c`）

- PDF document/page cleanup 保留原始异常，finish/close 失败按确定顺序加入 `suppressed`。
- active page 在调用 platform `finishPage` 前先 relinquish ownership，页面切换 finish 失败不会由外层 cleanup 对同一页重试。

## 15. 关键决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 架构路线 | Navigation Compose + Room + coroutine/Flow + 多模块 | 长期扩展、边界清晰、状态可测试 |
| Composition root | `:app` + 显式 `AppContainer` | 避免 feature 反向依赖与 Hilt 扩张 |
| 浓度来源 | 手机照片 tealness 插值 | 无酶标仪 OD；符合现有资产与产品限制 |
| 标准曲线 | 单调节点的分段线性逆 | 可解释、可校准；不进行无依据外推 |
| 平台信号逆 | 右连续，取完整平台最高浓度 | 对 PAVA/出厂等信号节点给出确定结果 |
| 校准拟合 | 精确结构验证 + PAVA + 15%/3 单点容差 | 阻止弱动态范围和过度修正曲线激活 |
| 图片上限 | 最长边 2048、2 的幂采样、EXIF 旋转 | 降低 OOM 风险且保持可预测尺寸 |
| 检测提交 | SavedStateHandle draft + Room unique draft ID | 重建/重试不重复写入 |
| 相机权限 | durable intent + claim/ack/rollback | 覆盖 Activity Result、重建和同步失败竞态 |
| 校准写协调 | process Mutex 统一 user save/legacy promotion/clear | 防止旧曲线或清空覆盖新用户校准 |
| 报告 | shared model + Locale formatter + 多页 PDF | 文本/PDF语义一致，可验证双语与完整性 |
| 声明位置 | 关于页和导出报告；Result 不显示 | 用户确认；报告已完成，关于页待 Phase 3 |
| 返回策略 | 路由栈回上一页；Home 根才退出 | 避免普通 Back 直接退出应用 |
