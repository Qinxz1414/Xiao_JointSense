## 1. 产品定位与使用边界

JointSense 是面向骨关节炎（OA）科研与纵向趋势观察的 Android 应用。用户可以拍摄或选择 ELISA 检测板照片，裁剪目标区域，选择 TNF-α、IL-6 或 IL-1β，使用照片 RGB 色度代理信号和标准曲线得到浓度估算，并查看历史、趋势、OA 炎症综合指数、等级和导出报告。

应用已实现：

- 相机与 Photo Picker 选图、方向修正、采样解码、裁剪、因子选择、分析、幂等保存和继续检测；
- TNF-α、IL-6、IL-1β 三因子浓度、范围状态和 RGB 均值/标准差记录；
- 3×3 标准梯度板校准、Blank 扣除、单调拟合、旧曲线复核和恢复出厂曲线；
- Home、Trends、Report、History、Profile、About 与检测/校准子流程；
- 结构化中英文文本/PDF 报告及系统分享；
- 跟随系统、简体中文和英文切换，并在 Activity 重建后保持导航与业务状态；
- 科研/临床专业品牌、深浅色主题、无障碍语义、非颜色图表区分和 200% 字体适配。

科学与合规边界不可弱化：

- 图像信号是 `tealness = bMean - rMean` 的手机照片色度代理，不是酶标仪 OD；
- 标准曲线是可解释的分段线性量化，不是经临床验证的诊断模型；
- 结果仅用于科研和纵向趋势观察，不用于临床诊断、治疗决策，也不替代经验证的实验室检测；
- 固定声明显示在 About 页面和导出报告中，Result 页面按产品决策不重复显示。

依赖方向：

```text
core:domain       -> Kotlin / Flow
core:analysis     -> core:domain
core:image        -> Android / ExifInterface
core:designsystem -> core:domain + Compose
core:database     -> core:domain + Room
core:data         -> core:domain + core:database
```

## 4. 类型安全导航与返回行为

### 4.1 路由图

顶层路由为 `HomeRoute`、`TrendsRoute`、`ReportRoute`、`ProfileRoute`；`HistoryRoute` 和 `AboutRoute` 是从 Profile 打开的普通目的地。底栏的中央“新建检测”是动作，不是常驻 tab。

```text
MeasurementGraph(origin)
└── ImageSelectRoute -> CropRoute -> FactorSelectRoute -> ResultRoute(resultId)

CalibrationGraph
└── CalibrationSelectRoute -> CalibrationCropRoute -> CalibrationAssignRoute
    -> CalibrationReviewRoute -> CalibrationDoneRoute
```

所有 graph/route 都由 Kotlin Serialization 表达；`TopLevelDestination` 带 `@Keep`，避免压缩构建破坏 enum serializer。

### 4.2 Back 与 origin

- 顶层页面保留实际访问历史；Back 返回上一个页面，最终回到 Home；只有 Home 根由 Activity/系统退出应用。
- About、History 等普通目的地 `popBackStack()` 返回来源页。
- 检测 Crop Back 返回 ImageSelect；Factor Back 返回保留裁剪状态的 Crop。
- 分析、持久化或结果交接的关键忙碌阶段会消费 Back，避免破坏资源/提交所有权。
- Result 从活动检测图进入时，顶部 Back、系统 Back 和预测性 Back 都弹出整个 `MeasurementGraph`，回到记录的 `origin`，不会退回 FactorSelect。
- 从 History 打开的历史 Result 只弹出当前结果页。
- Continue measurement 先退出当前检测图，再以同一 origin 创建新 graph、新 draft。
- 校准 Back 每次退一个 typed route；Done/明确退出会弹出整个 `CalibrationGraph`。

## 5. Room 数据模型、仓库与隐私

Room 数据库 `JointSenseDatabase` 当前 schema version 为 1，导出 schema。表如下：

| 表 | 主键/关系 | 主要字段 |
|---|---|---|
| `test_session` | `id` | name、createdAt、`USER/BUILT_IN` source |
| `test_result` | `id`；`sessionId` 外键级联 | nullable unique `draftId`、factor、concentration、rangeStatus、timestamp、6 个 RGB 特征 |
| `calibration` | factor | createdAt、version、`ACTIVE/NEEDS_REVIEW`、kit name/lot |
| `calibration_knot` | factor + position；外键级联 | concentration、raw/net/fitted signal、Blank 标记 |
| `app_metadata` | key | 迁移状态、样例初始化等稳定元数据 |

领域层定义 repository contract；`core:data` 中的 Room 实现提供 `Flow` 连续读取。跨表写入、全量清理和旧数据导入使用 Room 事务。`commitResult` 先按唯一 `draftId` 查询：同一草稿重试返回既有 result ID，不写重复结果。

### 5.1 内置样例与数据管理

- 首次无旧会话时初始化 12 个稳定 `BUILT_IN` 会话：9 组测试梯度和 3 组照片板数据；
- 自动初始化只发生一次，不覆盖用户数据；
- `restoreBuiltInSamples()` 显式且幂等，只恢复内置样例；
- `clearAllData()` 删除会话/结果和用户校准，并保留 `samplesInitialized=true`，重启不会自动回填；
- Profile 中恢复样例和清空全部数据都使用明确范围说明、确认对话框、加载/错误/重试状态。

### 5.2 旧数据迁移

旧 `joint_sense_data` / `joint_sense_calibration` SharedPreferences 只由 `LegacyMigrationCoordinator` 读取：

- 先严格解析全部 payload，再在一个 Room 事务中导入；任一条损坏会拒绝整批，事务回滚且不写完成标记；
- 旧结果缺失的新字段映射为 `RangeStatus.UNKNOWN` 和 `draftId=null`；
- 可解析的旧校准先写为 `NEEDS_REVIEW`，只有通过当前 validator 才提升为 `ACTIVE`；
- `Completed` / `AlreadyCompleted` 才进入主界面；失败可 Retry；
- 用户确认“空数据库开始”时，清理可能的部分 Room 数据并写 `SKIPPED_BY_USER`，但不删除旧文件；
- 跳过、失败和取消都不会偷偷把损坏数据当空数据成功。

生产代码中允许的 SharedPreferences 仅有两处：上述只读旧数据迁移来源，以及相机权限是否曾请求的历史。Room 是活动业务存储。

### 5.3 敏感数据备份策略

研究/健康测量只保存在应用本地。manifest 设置 `android:allowBackup="false"`；Android 12+ 的 data-extraction rules 同时排除 cloud backup 与 device transfer 的 root/file/database/sharedpref/external 及 device-protected 域。仓库中不保留默认备份 TODO 模板。

## 6. 图片与检测流水线

`core:image` 的 `SampledBitmapDecoder` 在 IO dispatcher 执行 bounds pass、2 的幂采样解码和 EXIF pass：最长边目标 2048，处理 4097 等向上边界，支持 90/180/270 度旋转。错误区分 Unsupported、Unreadable、OutOfMemory；成功才转移 bitmap 所有权，替换、失败和取消会释放本地资源。

检测流程：

```text
AwaitingImage -> Decoding -> ReadyToCrop -> ReadyToAnalyze
              -> Analyzing -> Persisting -> Success
              -> RecoverableError -> Retry(resumeStage)
```

- Photo Picker 使用 `PickVisualMedia(ImageOnly)`；尽量保留 provider 读权限，不支持时复制到 app-owned cache；
- 相机临时文件位于 `<cacheDir>/measurement` 的直接子项，URI/规范路径/token 一致时才允许删除；
- 特征为裁剪区 RGB 均值与总体标准差，量化信号固定为 `bMean - rMean`；
- 分析使用活动用户校准，否则使用 `FactoryCurves`；不经过占位回归模型；
- operation generation、draft identity 和 immutable snapshot 保证重复点击/晚到协程不会污染新流程；
- repository 成功返回后才进入 Success；持久化 Retry 复用同一 draft ID；
- 读取、解码、裁剪、分析、持久化、权限和文件清理错误均有可见状态和 Retry。

`SavedStateHandle` 保存 Bundle-safe 的 origin、draft、session、URI、crop 四边/确认态、factor、权限/相机请求 token、清理警告和待确认 result ID。Activity/进程内重建时 URI、crop、factor、draft、session、origin 和当前 route 均可恢复；bitmap 本身重新解码且 crop 重新校验实际尺寸。

相机权限采用 durable intent + request claim/ack/rollback 协议。首次点击不会在权限历史 IO 期间丢失；重复点击合并；同步 launcher 失败可恢复；过期 draft/token 的 Activity Result 被忽略；普通拒绝可重试，永久拒绝提供系统设置入口。

## 7. 校准与科学量化

### 7.1 校准验证

校准严格要求：

1. 恰好 9 条有限 raw signal；
2. 浓度文本按精确十进制语义解析，拒绝空白、非法、负数、NaN、Infinity、溢出和非零下溢；
3. 恰好一个 `concentration == 0` 的 Blank，非 Blank 浓度唯一；
4. `netSignal = rawSignal - blankRawSignal`，结果必须可表达为有限 Float；
5. net dynamic range 至少 8.0；
6. 按浓度排序后用 adjacent-block PAVA 得到非递减 fitted signal；
7. 单点允许修正为 `max(3.0, rawDynamicRange × 0.15)`，超过则 `NonMonotonicBeyondTolerance`；
8. 只有 `CalibrationValidation.Valid` 可保存为 `ACTIVE`。

校准保留 raw/net/fitted、孔位置、浓度、Blank、试剂盒名称/批号。Select → Crop → Assign → Review → Done 共用 graph-scoped `CalibrationViewModel`；factor、浓度原文、9 个 readings、URI、crop 和完成标记可重建。detect/save/restore 为 single-flight，busy 时锁定冲突输入。用户保存、旧曲线 promotion 和 factory clear 共用进程 Mutex，避免互相覆盖。

### 7.2 StandardCurve

- 节点要求浓度有限非负且严格递增，信号有限且非递减；测量输入必须有限；
- 节点间分段线性插值；低于首信号返回 0/`BELOW_RANGE`；高于末信号返回末浓度/`ABOVE_RANGE`，不外推；
- 精确平台采用右连续逆，返回整个平台最高浓度；
- 中间和最终浓度必须保持有限、非负且能以 Float 表达。

### 7.3 OA 炎症综合指数与等级

因子 caps：TNF-α 500、IL-6 1000、IL-1β 500 pg/mL；权重分别为 0.40、0.35、0.25。每项先按 cap 归一化到 0–1，再加权；缺失因子只在现有权重内重新归一化；空输入返回无指数；非有限输入被拒绝。

| 等级 | AI 区间 | 当前显示语义 |
|---|---|---|
| 0 | `[0, 0.25)` | 极低活动 / No risk |
| 1 | `[0.25, 0.50)` | 轻度 / Mild |
| 2 | `[0.50, 0.75)` | 中度 / Moderate |
| 3 | `[0.75, 0.90)` | 重度 / Severe |
| 4 | `[0.90, 1.00]` | 极重度 / Very severe |

## 8. 洞察、报告与术语

Home 显示当前 OA 炎症综合指数、等级、三因子最新值/小趋势和最近 AI 序列；Trends 支持 7/30/90 天及全部范围，显示三因子、AI 和关键事件；History 显示完整会话摘要并将“打开”和“删除”分成独立动作。

报告由共享结构化 `ReportModel` 驱动，UI、文本和 PDF 包含：生成时间、当前 AI/等级、三因子结果/范围、周趋势解释、科研趋势建议、方法说明与固定免责声明。PDF 支持多页、重复页眉、安全换行、同名冲突避免、完整写入后成功、分享失败反馈和 exactly-once 资源清理。

术语统一：

- `OA inflammation index (AI)` / `OA 炎症综合指数（AI）`；
- TNF-α、IL-6、IL-1β，浓度单位统一 `pg/mL`；
- “grade/等级”表示科研趋势分层，不称临床诊断分级；
- “tealness/蓝绿色度代理”与 OD 明确区分。
